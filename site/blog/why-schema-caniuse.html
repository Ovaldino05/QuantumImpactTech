Your tool schema works in Claude. Will it work in Gemini?

Structured outputs and tool calling look like a solved problem: you hand the model a JSON Schema and you get JSON back. In practice every provider accepts a different subset of JSON Schema, and they disagree on what to do with the rest.

Three providers, three behaviors

  • OpenAI strict mode rejects the request when the schema uses something it does not support, such as allOf. It also requires additionalProperties: false and every property listed in required.
  • Gemini accepts some keywords, like minLength, but does not enforce them. Nothing fails; your constraint just disappears.
  • Claude's SDK removes constraints such as maximum before sending and moves them into the description, and the API caps optional parameters per request.

The same schema can therefore fail loudly, fail silently, or be rewritten, depending on where it runs.

Everyone keeps their own list

Agent frameworks and SDKs work around this by shipping their own hand-written lists of "unsupported keywords" per provider. Each list is maintained separately, verified at a different date, and some of the public comparisons already contradict the providers' own documentation.

A shared, sourced database

schema-caniuse takes the approach that worked for browsers with caniuse: one shared dataset that everyone can depend on and fix.

  • Every fact cites the provider's official documentation and a verification date.
  • Anything undocumented is marked unknown instead of guessed.
  • A zero-dependency checker points to the exact JSON Pointer of each problem, for plain schemas and for MCP, OpenAI and Anthropic tool lists.
npx schema-caniuse tools.json --target openai-strict,gemini

How you can help

Providers change constantly, so the most valuable contribution is a data fix: edit one JSON file, cite the source, add a test. Start with a good first issue, or try the playground.
